# 관리자 화면 · BFF (4단계)

후속 [5단계 유저 관리](user-management-stage5.md)가 연결되어 회원 상세·권한 배정·계정 상태·닉네임 변경 이력을 제공한다. 아래 내용은 4단계에서 구성한 공통 화면/BFF 경계를 설명한다.

후속 [6단계 로그 조회](admin-logs-stage6.md)에서 활동 로그·관리자 작업 기록의 권한별 목록과 상세 모달을 연결했다.

## 진입과 제공 화면

공통 헤더의 **알림 바로 왼쪽 설정 아이콘**으로 `/admin`에 진입한다. 현재 로그인 세션과 `/api/admin/me`에서 `ADMIN_ACCESS`가 확인된 사용자에게만 아이콘을 표시한다. 사용자 이름이나 특정 역할 이름으로 표시 여부를 결정하지 않는다.

| 경로 | 화면 | 조회 기능 | 변경 기능 |
| --- | --- | --- | --- |
| `/admin/roles` | 검색·번호 페이지 방식의 역할 그리드, 행 선택 상세 모달, 분야별 기능 탭·선택, 추가·편집·삭제 | `ROLE_READ` | `ROLE_WRITE`, `ROLE_PERMISSION_UPDATE` |
| `/admin/operations` | 접속 제한 스위치, 사용자 안내, 접속 허용 역할 검색·선택 | `ACCESS_POLICY_READ` | `ACCESS_POLICY_UPDATE`, 예외 역할은 `ACCESS_EXEMPTION_UPDATE` |
| `/admin/games` | 게임 등록·표시 정보, 장르, 모드별 인원, 공개·점검 상태 | `GAME_READ` | `GAME_WRITE`, 운영 상태는 `GAME_AVAILABILITY_UPDATE` |
| `/admin/filters` | 장르·플레이 인원·그래픽 필터 추가·수정·삭제·순서·사용 여부 | `GAME_READ` | `GAME_WRITE` |

기본 진입은 허용된 첫 메뉴를 선택한다. 권한·예외 역할 관리는 현재 서버 정책상 ROOT 전용이다. 조회만 가능한 사용자는 편집 입력과 저장 동작을 사용할 수 없다. 알려진 메뉴라도 권한이 없으면 보호 데이터를 조회하지 않고 안내한다. 미등록 화면 경로는 404다.

권한 그리드는 DB의 `sort_order, code`를 사용해 ROOT → 관리자 → 매니저 → 유저 순서로 표시한다. ROOT의 표시 이름과 코드 모두 `ROOT`이며, [V27 적용 절차](../../../back/playground/docs/root-role-migration.md)에 따라 기존 최고 관리자 배정을 이전한다.

역할의 구분 컬럼과 기본/사용자 정의 배지는 제공하지 않는다. [V28 삭제 정책](../../../back/playground/docs/role-deletion-policy.md)에 따라 `system_role`을 제거하고 ROOT는 코드로 직접 보호해 삭제 버튼을 표시하지 않는다. 나머지는 최초 제공 여부와 관계없이 미사용이면 삭제할 수 있다. 삭제 직전 서버에서 회원 배정·접속 허용 설정·회원가입 기본값 USER 사용을 검사하고 거절하면 사용처별 안내 팝업을 중앙에 표시한다. 확인은 안내만 닫으며 상세·편집 초안은 유지한다.

권한 상세는 왼쪽 분야 탭과 오른쪽 기능 행을 사용한다. 분야별·전체 선택 개수와 기능 설명, ROOT 전용 잠금을 표시하며 좁은 모달에서는 분야를 선택 상자로 제공한다. 키보드 화살표·Home·End로 분야를 옮길 수 있고 저장·닫기는 고정 푸터에서 제공한다. 분야를 바꿔도 다른 분야의 선택을 유지하고 저장 후에도 상세와 현재 분야를 유지한다. 기능 검색과 변경 사유는 입력·전송하지 않는다.

권한 이름과 설명은 같은 높이의 한 줄 input을 사용하며 ROOT 전용 안내는 줄바꿈하지 않는다. 미저장 변경 확인창은 부모 상세와 스크롤 위치에 관계없이 화면 정중앙에 표시하고 확인 동작은 `닫기`로 표시한다. 다른 설정 적용·삭제 확인의 동작 이름은 각 명령을 따른다.

저장 성공은 본문 배너 대신 3초 동안 화면 상단 중앙 토스트로 알린다. 열린 모달 안에서도 읽을 수 있고 모달을 닫아도 남은 시간 동안 유지되며, 포커스·본문 높이·배경 조작을 바꾸지 않는다. 그리드는 마우스로 모달을 닫은 후 복귀한 포커스를 행 선택으로 강조하지 않으며 실제 키보드 포커스와 순서 편집 선택은 구분해 표시한다.

추가·삭제 성공과 모달 제거가 동시에 반영되면 토스트가 참조하던 이전 모달도 문서에서 분리될 수 있다. 이때는 연결 상태를 확인해 분리된 요소에서 `showPopover()`를 호출하지 않고 모달 감지가 본문으로 옮긴 뒤 표시한다. 저장 자체는 다시 요청하지 않는다.

기능에 필요한 조회·접근 권한은 서버 사전으로 함께 선택하고, 선행 권한을 해제하면 연결된 기능도 해제한다. 서버의 저장 보완과 실제 API 권한 검사는 [기능 권한 적용](../../../back/playground/docs/admin-permission-enforcement.md)을 따른다.

로그인 화면 미리보기·적용 범위, 역할별 회원 수, 변경 영향/최고 관리자 보호 패널은 제공하지 않는다. 신고·제재와 공지 배너도 범위에 포함하지 않는다. 사용자 관리와 로그/감사 조회는 후속 5·6단계에서 연결했고, 채팅 조회·실제 지표 대시보드·서비스 상태는 이후 단계다. 아직 연결하지 않은 화면을 가짜 데이터나 준비 메뉴로 채우지 않는다.

## 권한과 요청 보호

- `src/features/admin`에 계약, BFF 허용 목록, 요청 훅과 화면을 분리한다. 역할 수는 코드에 고정하지 않는다. 기능 코드는 배포된 서버 구현에 대응하는 안정적인 사전이다.
- 페이지의 서버 렌더링에는 보호 데이터를 넣지 않는다. 브라우저가 로그인 상태와 현재 DB 권한을 확인한 뒤 요청한다. UI의 표시 제한은 보조이며 Spring 필터·인터셉터·서비스가 매 요청 최신 권한을 검사한다.
- 기존 HttpOnly 암호화 쿠키, BFF 인증, 브라우저 키, 탭 잠금과 한 번의 만료 토큰 갱신을 재사용한다. 별도 관리자 토큰이나 Spring Security 역할 authority를 만들지 않는다.
- 관리자 요청은 `X-Expected-Session-ID`를 필수로 보내고 BFF가 현재 쿠키 세션과 비교한다. local/prod의 서명에는 `sid`, 메서드, 전체 경로·인코딩된 검색 쿼리, 실제 본문 해시를 결합한다. Spring은 `sid`를 현재 세션·nonce와 비교한다. 다른 인증 API의 서명 계약은 유지한다.
- `/api/admin/[...segments]`는 등록한 경로·메서드만 중계한다. 중복·알 수 없는 쿼리, 미등록 본문 필드와 `metadata` 하위 필드를 거절한다. GET 조회와 DELETE의 실제 본문은 허용하지 않으며 Next가 제공하는 빈 DELETE 스트림은 정상 처리한다. HEAD는 405다.
- 쿼리 길이와 페이지 크기, 최대 16KiB 관리자 JSON을 제한한다. 게임 정보 저장만 장르 연결·카드 라벨·한글 2,000자 설명을 함께 담을 수 있게 32KiB까지 허용하며 브라우저 증명과 BFF가 같은 상한을 사용한다. 기존 인증 요청의 4KiB 제한은 바꾸지 않는다.
- 응답 계약을 검증하고 허용한 필드만 복사한다. 관리자 응답은 `private, no-store`이며 Cookie/세션 헤더에 따라 구분한다. 토큰과 내부 실행 URL은 응답하지 않는다. 오류도 등록된 공개 코드·안내만 전달한다.
- 진입 정보는 헤더와 본문의 동시 요청을 합치고, 30초 및 탭 복귀 시 다시 확인한다. 확인 실패·계정 변경에는 이전 권한을 숨긴다. 권한 편집 성공 후 즉시 재검증한다.
- 브라우저의 `GET /api/admin/me`는 관리자 권한이 없는 계정에 `200`과 `null`을 반환한다. BFF는 Spring이 검증한 `ACCESS_DENIED`만 이 정상 조회 결과로 변환하고, 관리자 계정의 기존 응답 검증과 실제 관리 API의 403·로그인 만료·브라우저 증명 오류는 유지한다. 접근 불가 결과도 기존 5초 공유 캐시에 포함한다.

## 홈 게임 카드 라벨

게임 상세의 **게임 정보 → 홈 카드 라벨**에서 사용 중인 DB 필터 중 해당 게임에 맞는 항목을 개별 선택한다. 이 선택은 카드 표시와 홈 필터 검색에 함께 적용된다. 장르를 연결했거나 특정 모드를 지원하더라도 라벨을 선택하지 않은 게임은 해당 필터로 검색되지 않는다. 빈 선택에는 기본 라벨을 자동으로 추가하지 않는다. 선택을 변경하면 미리보기가 갱신되고 **게임 정보 저장**으로 확정한다.

`metadata.cardLabelCodes`는 최대 128개의 중복 없는 코드 배열이며 `GRAPHICS:TWO_D`, `GENRE:BOARD`, `PLAYERS:SINGLE`처럼 DB 필터의 유형과 영구 코드로 구성한다. Spring은 기존 `GAME_WRITE`, 게임 잠금, `expectedVersion`과 감사 기록을 재사용하고 연결하지 않은 장르나 구현이 지원하지 않는 그래픽·인원은 거절한다. 공개 카탈로그는 사용 중인 필터와 공개·지원 모드에 해당하는 선택만 전달한다. 미공개 모드 라벨은 선택을 보관하되 공개 후에 표시한다.

Flyway V25는 `tbl_game_card_label`을 만들고 기존 연결 장르를 초기 선택으로 보존한다. 이전에 자동으로 표시하던 그래픽·인원 라벨은 초기 선택에 넣지 않는다. 적용하려면 MVC 서버를 재시작해 V25를 실행하고 프론트엔드도 함께 반영한다.

## 게임 필터 관리

`/admin/filters`에서 장르·플레이 인원·그래픽을 하나의 목록으로 관리한다. 기존 `/admin/genres` 주소도 같은 화면으로 연결한다. 유형·사용 여부·이름/코드 검색을 제공하며 기본 표시 개수는 20개, 선택지는 20·30·40·50개다. 목록 하단의 전체 개수는 표시하지 않고 번호 페이지 탐색을 중앙에 배치한다.

목록 제목 옆의 동그라미 i는 마우스 호버·키보드 포커스·모바일 탭에서 “사용 중인 항목은 홈 필터에 표시돼요. 게임에서 선택한 라벨이 있을 때만 검색돼요.”를 보여 준다. Escape로 닫을 수 있다. 같은 안내를 상단 고정 배너로 반복하지 않는다.

사용 중인 항목은 연결 게임 수와 관계없이 홈 필터와 미리보기에 전체 순서대로 표시된다. 유형과 코드는 생성 후 고정한다. 게임에 연결된 항목은 삭제할 수 없고 인원·그래픽 조건도 바꿀 수 없으며, 이름·아이콘·사용 여부는 수정할 수 있다. 삭제 가능한 항목을 지우면 전체 순서를 빈틈없이 정리한다. 연결된 게임이나 라벨을 자동 해제하지 않는다.

Flyway V26은 기존 장르 ID·순서·사용 여부·게임 연결을 보존하며 `tbl_game_filter`로 확장한다. 기존에 선택한 인원·그래픽 라벨과 사용자 정의 인원 범위도 DB 필터 코드로 옮긴다. 새 기본 인원·그래픽 항목은 이전 선택이 있었던 경우에만 사용 상태를 복원한다. MVC 서버 재시작으로 V26을 적용하고 프론트엔드를 함께 반영한다. 공개 `/api/game-filters`와 관리 `/api/admin/game-filters`는 기존 BFF·관리자 권한 경계를 따른다.

## 편집과 운영 동작

모든 변경은 조회한 `expectedVersion`을 사용한다. 다른 관리자가 먼저 저장한 409는 입력을 임의로 덮어쓰거나 변경 명령을 자동 재전송하지 않고 최신 내용을 다시 불러오도록 안내한다. 이전 세션과 취소된 검색 응답은 현재 편집을 덮어쓰지 않는다. 저장 토스트는 폼의 버전 변경 뒤에도 남은 표시 시간을 유지한다.

접속 제한과 예외 역할은 **각각 저장**한다. 제한을 활성화하거나 제한 중 예외 역할을 바꾸는 동작은 실행 직전 대화상자로 확인한다. ROOT와 예외 역할 이외의 기존 세션은 종료되고 새 로그인도 거절된다. 제한 해제/예외 재추가는 이미 종료한 세션을 복원하지 않는다.

게임과 모드의 표시 정보·운영 상태는 별도 권한과 명령을 사용한다. 숨김은 공개 목록뿐 아니라 직접 주소의 새 실행·입장도 차단한다. 진행 중인 판은 유지한다. 실제 서버가 지원하는 게임·이미지·모드만 선택한다. 새 게임/모드는 숨김·이용 중지 상태로 등록되며 모드와 공개 상태를 추가 설정해야 한다. 2D/3D, 로컬/온라인, 1인/경쟁/협동과 지원 인원 범위는 모드 정의에서 읽는다.

## 반응형과 확장

기존 로비의 배경·SVG 아이콘·글꼴·공통 1px 포커스를 재사용한다. [페이지 공통 크기 기준](responsive-layout.md)에 따라 관리 화면은 FHD 1600px에서 QHD 약 2133px, 4K 2500px까지 넓어지고 글자·컨트롤은 기본 크기의 최대 125%까지만 완만하게 커진다. 본문은 메뉴·실제 내용 높이에서 멈춘다. 작은 화면은 가로 메뉴와 위아래 목록/상세, 넓은 화면은 사이드 메뉴와 목록/상세 두 영역을 사용한다. 역할/장르는 커서로 탐색하며 다른 페이지에서 선택한 항목도 보존한다. 모드는 선택한 한 개의 폼만 만든다.

관리자 공통 레이아웃은 연결 메뉴형을 사용한다. 사이드바는 기존 배경 위에 배치하고 선택 메뉴의 흰색 면과 바깥 곡선을 오른쪽 본문에 붙인다. 본문은 제목과 기존 기능 패널을 포함하는 하나의 흰색 영역이다. `AdminNavigation`은 상위에서 조회 권한으로 걸러 전달한 메뉴만 표시하며 `aria-current`와 공통 1px 키보드 포커스를 유지한다. 980px 이하에서는 본문 위에 붙는 가로 탭으로 전환하고 메뉴 선택·창 크기 변경·화면 회전 시 현재 메뉴를 보이는 위치로 이동한다. 본문에는 표·폼·모달 기능을 배치한다.

게임·필터·회원·로그·채팅 그리드는 현재 페이지의 행 수에 맞춰 높이가 늘어나며 내부 세로 스크롤을 만들지 않는다. 표 위에서도 휠로 페이지 전체를 이동할 수 있고, 좁은 화면의 가로 이동은 표 영역에서 처리한다. 순서 편집 중 드래그 손잡이를 화면 위·아래 가장자리로 옮기면 그리드 대신 페이지가 이동한다.

새 화면을 추가할 때 서버 기능 권한·응답 DTO를 먼저 확정하고 `contracts.ts` 파서, BFF의 경로/본문 허용 목록, 메뉴의 조회 권한, 패널을 함께 추가한다. 사용자 역할 배정 API는 이미 Spring에 있지만 이 단계에서 회원 ID 수동 입력 화면이나 임의 프록시로 공개하지 않는다. 사용자 검색/상세 개발 때 연결한다.

최초 SUPER_ADMIN은 [서버 초기 설정](../../../back/playground/docs/authorization-stage1.md)을 따른다. 화면 개발 검증은 격리된 계정으로 수행했으며, 후속 작업인 2026-10-24 [실제 초기 배정](../../../back/playground/docs/super-admin-initialization-2026-10-24.md)에서 지정한 기존 로그인 아이디 `admin`에 SUPER_ADMIN을 적용했다. 실제 계정 배정 또는 역할 변경으로 종료된 기존 세션은 다시 로그인해야 한다.

검증 증거는 [4단계 결과](../../../artifacts/admin-development-stage4/verification.md)에 보관한다. 새 검증 소스와 임시 실행 파일은 검증 후 삭제한다.
