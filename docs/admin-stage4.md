# 관리자 화면 · BFF (4단계)

후속 [5단계 유저 관리](user-management-stage5.md)가 연결되어 회원 상세·권한 배정·계정 상태·닉네임 변경 이력을 제공한다. 아래 내용은 4단계에서 구성한 공통 화면/BFF 경계를 설명한다.

후속 [6단계 로그 조회](admin-logs-stage6.md)에서 활동 로그·관리자 작업 기록의 권한별 목록과 상세 모달을 연결했다.

## 진입과 제공 화면

공통 헤더의 **알림 바로 왼쪽 설정 아이콘**으로 `/admin`에 진입한다. 현재 로그인 세션과 `/api/admin/me`에서 `ADMIN_ACCESS`가 확인된 사용자에게만 아이콘을 표시한다. 사용자 이름이나 특정 역할 이름으로 표시 여부를 결정하지 않는다.

| 경로 | 화면 | 조회 기능 | 변경 기능 |
| --- | --- | --- | --- |
| `/admin/roles` | 검색·커서 방식의 동적 역할 목록, 기능 그룹 검색·선택, 추가·편집·삭제 | `ROLE_READ` | `ROLE_WRITE`, `ROLE_PERMISSION_UPDATE` |
| `/admin/operations` | 접속 제한 스위치, 사용자 안내, 접속 허용 역할 검색·선택 | `ACCESS_POLICY_READ` | `ACCESS_POLICY_UPDATE`, 예외 역할은 `ACCESS_EXEMPTION_UPDATE` |
| `/admin/games` | 게임 등록·표시 정보, 장르, 모드별 인원, 공개·점검 상태 | `GAME_READ` | `GAME_WRITE`, 운영 상태는 `GAME_AVAILABILITY_UPDATE` |
| `/admin/genres` | 장르 추가·이름·노출 순서·사용 여부 | `GAME_READ` | `GAME_WRITE` |

기본 진입은 허용된 첫 메뉴를 선택한다. 권한·예외 역할 관리는 현재 서버 정책상 SUPER_ADMIN 전용이다. 조회만 가능한 사용자는 편집 입력과 저장 동작을 사용할 수 없다. 알려진 메뉴라도 권한이 없으면 보호 데이터를 조회하지 않고 안내한다. 미등록 화면 경로는 404다.

로그인 화면 미리보기·적용 범위, 역할별 회원 수, 변경 영향/최고 관리자 보호 패널은 제공하지 않는다. 신고·제재와 공지 배너도 범위에 포함하지 않는다. 사용자 관리와 로그/감사 조회는 후속 5·6단계에서 연결했고, 채팅 조회·실제 지표 대시보드·서비스 상태는 이후 단계다. 아직 연결하지 않은 화면을 가짜 데이터나 준비 메뉴로 채우지 않는다.

## 권한과 요청 보호

- `src/features/admin`에 계약, BFF 허용 목록, 요청 훅과 화면을 분리한다. 역할 수는 코드에 고정하지 않는다. 기능 코드는 배포된 서버 구현에 대응하는 안정적인 사전이다.
- 페이지의 서버 렌더링에는 보호 데이터를 넣지 않는다. 브라우저가 로그인 상태와 현재 DB 권한을 확인한 뒤 요청한다. UI의 표시 제한은 보조이며 Spring 필터·인터셉터·서비스가 매 요청 최신 권한을 검사한다.
- 기존 HttpOnly 암호화 쿠키, BFF 인증, 브라우저 키, 탭 잠금과 한 번의 만료 토큰 갱신을 재사용한다. 별도 관리자 토큰이나 Spring Security 역할 authority를 만들지 않는다.
- 관리자 요청은 `X-Expected-Session-ID`를 필수로 보내고 BFF가 현재 쿠키 세션과 비교한다. local/prod의 서명에는 `sid`, 메서드, 전체 경로·인코딩된 검색 쿼리, 실제 본문 해시를 결합한다. Spring은 `sid`를 현재 세션·nonce와 비교한다. 다른 인증 API의 서명 계약은 유지한다.
- `/api/admin/[...segments]`는 등록한 경로·메서드만 중계한다. 중복·알 수 없는 쿼리, 미등록 본문 필드와 `metadata` 하위 필드를 거절한다. GET 조회와 DELETE의 실제 본문은 허용하지 않으며 Next가 제공하는 빈 DELETE 스트림은 정상 처리한다. HEAD는 405다.
- 쿼리 길이와 페이지 크기, 최대 16KiB 관리자 JSON을 제한한다. 한글 2,000자 게임 설명이 기존 인증의 4KiB 제한에 걸리지 않도록 관리자 본문만 별도 제한한다. 기존 인증 요청 제한은 바꾸지 않는다.
- 응답 계약을 검증하고 허용한 필드만 복사한다. 관리자 응답은 `private, no-store`이며 Cookie/세션 헤더에 따라 구분한다. 토큰과 내부 실행 URL은 응답하지 않는다. 오류도 등록된 공개 코드·안내만 전달한다.
- 진입 정보는 헤더와 본문의 동시 요청을 합치고, 30초 및 탭 복귀 시 다시 확인한다. 확인 실패·계정 변경에는 이전 권한을 숨긴다. 권한 편집 성공 후 즉시 재검증한다.
- 브라우저의 `GET /api/admin/me`는 관리자 권한이 없는 계정에 `200`과 `null`을 반환한다. BFF는 Spring이 검증한 `ACCESS_DENIED`만 이 정상 조회 결과로 변환하고, 관리자 계정의 기존 응답 검증과 실제 관리 API의 403·로그인 만료·브라우저 증명 오류는 유지한다. 접근 불가 결과도 기존 5초 공유 캐시에 포함한다.

## 편집과 운영 동작

모든 변경은 조회한 `expectedVersion`을 사용한다. 다른 관리자가 먼저 저장한 409는 입력을 임의로 덮어쓰거나 변경 명령을 자동 재전송하지 않고 최신 내용을 다시 불러오도록 안내한다. 이전 세션과 취소된 검색 응답은 현재 편집을 덮어쓰지 않는다. 저장 결과는 폼의 버전 변경 뒤에도 상단에 남는다.

접속 제한과 예외 역할은 **각각 저장**한다. 제한을 활성화하거나 제한 중 예외 역할을 바꾸는 동작은 실행 직전 대화상자로 확인한다. 슈퍼 관리자와 예외 역할 이외의 기존 세션은 종료되고 새 로그인도 거절된다. 제한 해제/예외 재추가는 이미 종료한 세션을 복원하지 않는다.

게임과 모드의 표시 정보·운영 상태는 별도 권한과 명령을 사용한다. 숨김은 공개 목록뿐 아니라 직접 주소의 새 실행·입장도 차단한다. 진행 중인 판은 유지한다. 실제 서버가 지원하는 게임·이미지·모드만 선택한다. 새 게임/모드는 숨김·이용 중지 상태로 등록되며 모드와 공개 상태를 추가 설정해야 한다. 2D/3D, 로컬/온라인, 1인/경쟁/협동과 지원 인원 범위는 모드 정의에서 읽는다.

## 반응형과 확장

기존 로비의 배경·SVG 아이콘·글꼴·2560px 최대 콘텐츠 너비·공통 1px 포커스를 재사용한다. 작은 화면은 가로 메뉴와 위아래 목록/상세, 넓은 화면은 사이드 메뉴와 목록/상세 두 영역을 사용한다. 역할/장르는 커서로 탐색하며 다른 페이지에서 선택한 항목도 보존한다. 모드는 선택한 한 개의 폼만 만든다.

새 화면을 추가할 때 서버 기능 권한·응답 DTO를 먼저 확정하고 `contracts.ts` 파서, BFF의 경로/본문 허용 목록, 메뉴의 조회 권한, 패널을 함께 추가한다. 사용자 역할 배정 API는 이미 Spring에 있지만 이 단계에서 회원 ID 수동 입력 화면이나 임의 프록시로 공개하지 않는다. 사용자 검색/상세 개발 때 연결한다.

최초 SUPER_ADMIN은 [서버 초기 설정](../../../back/playground/docs/authorization-stage1.md)을 따른다. 화면 개발 검증은 격리된 계정으로 수행했으며, 후속 작업인 2026-10-24 [실제 초기 배정](../../../back/playground/docs/super-admin-initialization-2026-10-24.md)에서 지정한 기존 로그인 아이디 `admin`에 SUPER_ADMIN을 적용했다. 실제 계정 배정 또는 역할 변경으로 종료된 기존 세션은 다시 로그인해야 한다.

검증 증거는 [4단계 결과](../../../artifacts/admin-development-stage4/verification.md)에 보관한다. 새 검증 소스와 임시 실행 파일은 검증 후 삭제한다.
