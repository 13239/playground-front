# 슈팅 초대·처치 효과·무적 표시 개선

검증일: 2026-10-30

## 입장과 초대 응답

친구 초대 수락·초대 링크·방 코드 직접 참여는 비밀방도 비밀번호 입력 없이 바로 참가한다. 방 목록에서 비밀방을 선택하는 일반 참여는 기존 비밀번호 입력을 사용한다. 코드를 아는 사용자의 직접 참여를 허용하는 것이 이번 요청의 입장 정책이다.

코드 참여는 BFF와 Spring에서 8자리 협동 방 코드를 검증하고, 그 방에 한정된 입장 권한을 Redis 일회용 티켓의 내부 신원에 기록한다. 게임 서버는 티켓을 소비하고 정확한 방 일치 여부를 확인한다. 클라이언트 접속 옵션에 임의의 플래그를 넣는 것으로 비밀번호 검증을 생략할 수 없다. 공개 티켓 응답과 URL에 비밀번호·내부 권한은 넣지 않는다. 로그인·브라우저 키·Origin·참가 인원·방 상태·게임 사용권 검증은 계속 적용한다.

초대 수락 뒤 비밀번호 창을 다시 여는 흐름을 제거했다. 같은 슈팅 화면에 이미 다른 연결이 있어도 새 방 코드를 처리하고, 이전 방의 사용권 반환을 기다린 뒤 참가한다. 소비한 URL의 처리 기록은 초기화해 같은 방의 새 초대도 다시 수락할 수 있다.

15초는 최초 응답 기한으로 사용한다. 이미 수락한 응답의 재조회는 원래 기한이 지났다는 이유만으로 취소하지 않는다. 방 버전·친구 관계·방 상태가 바뀌면 기존대로 거절한다. 클라이언트는 응답 처리 중인 카드가 시간 만료만으로 사라지지 않게 처리 문구를 표시하고, 실패 안내는 카드 밖의 공통 안내에도 남긴다.

## 처치와 보호 상태

- 일반 처치는 12개 파편을 0.85초, 보스는 24개 파편을 1.1초 표시한다. 파편의 크기·대비·이동 거리를 늘리고 밝은 테두리·잔궤적·짧은 파열 섬광을 더했다. 초반에 빠르게 벌어진 뒤 회전·낙하하며 후반에 사라진다.
- 효과 상한 160개는 유지한다. 상한에 닿았을 때 처치 효과는 작은 피격 스파크 한 개를 대체한다. 실제 피해·성장 판정에는 영향을 주지 않는다.
- 보호 중인 캐릭터는 보라색 몸체와 밝은 이중 육각 장갑을 사용한다. 본인 주변에는 `무적 1.9초`처럼 남은 보호 시간을 0.1초 단위로 표시한다. 아이템 무적뿐 아니라 서버가 부여한 피격·부활 보호도 같은 보호 상태로 표시한다.
- 시간 표시는 재사용하는 Phaser Text 한 개로 처리한다. 작은 화면에서는 표시 크기를 최소 약 14.4 CSS px로 유지하고 아래쪽 경계 근처에서는 캐릭터 위로 옮긴다. 시간이 끝나거나 전투 불능이 되면 숨긴다.
- 효과와 보호 시간의 표시는 서버 패치 사이에서 최대 0.15초만 보간한다. 일시정지·연결 복구 중에는 보간하지 않는다. 서버의 무적 판정·아이템 수량·쿨다운·피해 계산은 변경하지 않았다.

## 검증

- 프론트 TypeScript·변경 파일 ESLint·Next.js 16.4.2 프로덕션 빌드 통과. 게임 서버 TypeScript 검사와 Spring Boot MVC Java 컴파일 통과.
- Spring 임시 회귀 테스트 9개 통과: 참가권의 정확한 코드·협동 모드 제한, 내부 신원과 공개 응답의 분리, 일반 입장, 최초 수락·만료·수락 응답 재조회·변경된 방·다른 수신자·참가 불가 상태.
- 실제 Colyseus 게임 서버·SDK와 모의 Spring 내부 API를 연결한 13개 검증 통과. 친구 초대·링크·코드 참가권의 비밀번호 없는 입장, 일반 비밀번호 검증, 잘못된 비밀번호·임의 옵션·다른 방 참가권·재사용 티켓·만석 거절을 확인했다. 원본 시뮬레이션의 실제 무적 피해 방지, 정지 시 보호 시간 유지, 파편 수명과 효과 상한도 검증했다.
- Chrome 156.0.8078.48과 Edge 156.0.4314.50에서 실제 화면 컴포넌트·소셜 저장소와 모의 인증·입장 API를 사용해 링크·코드의 즉시 입장, 같은 화면의 다른 방 초대, 느린 수락 응답이 기한을 넘는 경우, 같은 방 재초대를 확인했다.
- 두 브라우저에서 원본 Phaser 4.2.1 렌더러로 파편 초기·후반과 보호막·소수점 시간 표시를 확인했다. 보호 종료 시 숨김과 정지 상태의 표시를 확인했다. 화면 크기·캔버스 크기·카메라 확대가 모두 바뀐 뒤 측정했다.
- 브라우저 배율 100%, CSS viewport 320×568, 390×844, 844×390, 768×1024, 1024×768, 1280×720, 1920×1080, 2560×1440, 3840×2160, 5120×2880에서 독립 전장 렌더러의 가로 넘침과 보호 시간 가독성을 확인했다. 이 검증은 전장 표시 검증이며 전체 게임 페이지의 모든 메뉴를 각 크기에서 재검증한 것은 아니다.
- 결과 XML·JSON과 화면은 프로젝트 루트의 `artifacts/shooting-invitations-effects-2026-10-30/`에 보존한다. 검증 후 이번에 만든 테스트 소스와 임시 서버를 제거했다. 기존 테스트는 유지했다.

실제 로그인 계정·MySQL·Redis·채팅·게임 서비스를 함께 연결한 전체 통합 플레이, 실제 두 계정의 장시간 플레이, Firefox·Safari는 미검증이다. 참고한 공식 문서는 [Colyseus Room](https://docs.colyseus.io/room), [Phaser Graphics](https://docs.phaser.io/api-documentation/class/gameobjects-graphics)다. 설치된 Next.js의 로컬 서버·클라이언트 컴포넌트 문서도 확인했다.

## 반영

프론트 변경과 함께 Spring 백엔드와 Node 게임 서버를 재시작해야 참가권 계약과 시각 효과 수명이 일치한다. 이번 슈팅 개선에는 추가 DB 마이그레이션이 없다. 채팅 서버의 소스 변경은 없다.
