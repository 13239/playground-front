# 로그 조회 화면 (6단계)

헤더 알림 왼쪽 설정 아이콘 → **로그 조회**, 또는 `/admin/logs`로 진입한다. 승인한 [디자인 시안](../../../artifacts/admin-log-design-stage6-2026-10-25/design-notes.md)의 보라색 탭·그리드·중앙 상세 모달을 기존 관리자 화면에 연결했다.

## 구성과 권한

- 사용자 활동 로그: `ACTIVITY_LOG_READ`. 로그인·회원가입의 성공/실패를 기간·회원·활동·결과로 검색한다.
- 관리자 작업 기록: `ADMIN_AUDIT_READ`. 기간·관리자·작업·대상 종류로 검색한다. 작업 당시 권한 코드와 기존 변경 사유를 표시한다.
- 두 권한 중 하나만 있어도 메뉴를 표시하고 해당 탭만 조회한다. 두 권한이 모두 없으면 메뉴를 숨기고 직접 경로 접근도 안내 화면으로 처리한다. 최종 권한 검사는 서버가 수행한다.
- 관리자 작업에 존재하지 않는 성공/실패·접속 IP 컬럼은 추가하지 않았다. 로그 변경·삭제·내보내기·되돌리기·통계 카드도 없다.

기본 기간은 한국 날짜 기준 최근 7일이다. 필터는 검색 버튼으로 함께 적용하고 잘못된 기간에는 입력 오류를 표시한다. 표시 개수는 우측에서 10/20/30/50개(기본 10개)를 선택한다. 검색과 표시 개수 변경은 첫 페이지로 돌아간다. 첫·이전·번호·다음·마지막 버튼과 시계방향 새로고침 아이콘은 기존 공통 컴포넌트를 사용한다.

그리드 행 또는 기록 번호를 누르면 상세 모달을 연다. Escape·상단 닫기·하단 닫기를 지원하며 닫으면 원래 기록 번호 버튼으로 초점과 배경 스크롤을 복원한다. 활동 상세에는 기록된 브라우저와 입력 식별자를 표시하고, 작업 상세에는 저장된 변경 전/후·기존 사유를 표시한다. 개인정보 조회 사유 입력이나 마스킹 기능을 추가하지 않았다.

## 파일

- `components/logs-panel.tsx`: 권한별 탭, 날짜/검색 필터, 목록·페이징.
- `components/log-details-dialog.tsx`: 읽기 전용 활동/작업 상세 모달.
- `components/log-person.tsx`: 기록의 회원 번호·공개 프로필·시스템/미확인 회원 표시.
- `components/logs.module.css`: 필터 줄바꿈, 표 내부 가로/세로 스크롤, 모달 내용 배치.
- `log-contracts.ts`: 종류별 응답의 허용 필드 복사·검증. 원문 JSON은 계약에 없다.
- `log-search.ts`: 한국 날짜 기본 기간과 실제 달력 날짜 검사.
- `pagination-contracts.ts`: 유저 관리와 로그가 공유하는 번호 페이지 검증. 기존 역할·게임 등 커서 계약은 그대로다.
- `server/routes.ts`: 두 종류의 GET 목록/옵션/상세만 BFF 허용 목록에 등록한다. 중복 조건, 잘못된 날짜, 임의 필드와 변경 메서드는 거절한다.

이름·사유·브라우저·변경 값은 HTML로 해석하지 않고 React 텍스트로 출력한다. 원문 로그나 토큰을 브라우저 저장소에 넣지 않는다. 계정/탭/기록 변경 시 취소된 응답은 새 상세를 덮어쓰지 않는다.

반응형은 필터 줄바꿈과 표 내부 스크롤을 사용한다. 모달은 뷰포트 안에 두고 내용만 스크롤해 닫기를 계속 사용할 수 있다. 실제 320/390/768/1920/2560/3840/5120px에서 두 목록·두 상세, 총 28개 배치를 검증했다.

백엔드와 조회 계약을 함께 반영하고 **백엔드를 재시작해 V18을 적용**해야 한다. 새 환경 변수는 없다. [서버 계약](../../../back/playground/docs/admin-logs-stage6.md), [검증 결과·실제 화면](../../../artifacts/admin-development-stage6/verification.md)을 참조한다.
