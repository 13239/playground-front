# 슈팅게임 다크 시네마틱 UI

2026-11-05 사용자가 선택한 2번 시안을 슈팅게임 전체에 적용했다. 기존 맵·캐릭터 원화를 재사용하며 실제 플레이·방 참가·해금·기록 API 계약은 유지한다.

## 적용 화면

- 모드 선택: 큰 표지와 읽기 쉬운 제목, 모험/PVP 카드, 준비 중 PVP 안내.
- 맵 선택: 선택한 맵의 큰 전경, 오른쪽 목표 시간·플레이 방식·출격 설정, 아래 여섯 맵 목록. 검색·필터·번호 페이지·잠긴 맵 미리보기와 서버의 출격 검증을 유지한다.
- 협동 방 목록·빈 목록·검색·코드 참가·방 만들기·공개/비밀방·비밀번호 입력.
- 1인 캐릭터/무기 선택과 협동 대기실·맵 선택·친구 초대.
- 전투 HUD·진행도·강화 선택·일시정지·연결 안내·종료 확인·결과·랭킹·조작 안내·지형 미리보기.
- 게임 헤더·사이트 탐색/푸터 표면·로그인 안내도 슈팅 화면의 다크 톤과 연결한다.

## 구조와 반응형

`shooting-theme.module.css`가 배경·표면·글자·경계·선택·강조 색상을 관리한다. 공통 검색/선택/모달에는 기본 색상을 보존하는 선택적 CSS 토큰을 사용한다. `ShootingRoomDialog`는 body 또는 전체 화면 요소에 포털로 표시되는 모달에도 같은 토큰을 전달한다. 친구 초대는 선택적인 `className`만 받아 기존 인증·초대 처리 경계를 공유한다. 다른 게임에 슈팅 테마를 전역 적용하지 않는다.

FHD에서는 장식 이미지 높이와 여백을 먼저 조정해 주요 동작을 같은 화면에 둔다. 고해상도는 기존 rem·페이지 폭 토큰으로 확장하고, 좁은 화면에서는 맵 목록을 3열/2열로 바꾸며 상세·설정을 세로로 재배치한다. 480px 이하는 게임 제목과 상단 조작을 두 행으로 나눠 최소 터치 영역을 유지한다. 모바일과 내용이 많은 창의 필요한 세로 스크롤은 허용한다.

맵 전경 아틀라스는 컨테이너의 긴 변을 기준으로 정사각 셀을 잘라 세로 방 생성 카드에서도 원화 비율과 맵 경계를 지킨다. `useArenaViewport`는 문서 기준 위치로 높이를 계산하므로 스크롤한 상태에서 창 크기를 바꿔도 전장 높이를 불필요하게 늘리지 않는다. 협동 목록은 바깥 복귀 버튼과 허브 여백의 높이를 따로 제외한다.

## 검증

- Next.js 16.4.2 프로덕션 빌드·전체 TypeScript 검사·슈팅 컴포넌트/높이 계산 훅/초대 모달 ESLint 통과.
- Chrome 156.0.8078.81, Edge 156.0.4314.58, Firefox 150.0.2, WebKit 26.4에서 실제 컴포넌트와 CSS를 렌더링했다. API·인증·플레이어·게임 상태는 가상 응답/픽스처를 사용했다.
- 13개 화면 상태 × 13개 CSS 뷰포트 × 4개 브라우저 = 676개 배치 검사. 너비 넘침과 표시된 조작 요소의 가로 이탈이 없었다. FHD 1920×1080에서는 방 목록·대기실을 포함한 모든 검증 화면이 한 화면에 들어왔다.
- 뷰포트(배율 100%): 1920×1080, 1920×900, 2560×1440, 3840×2160, 5120×2880, 390×844, 844×390, 768×1024, 1024×768, 320×568, 1280×650, 600×700, 1920×600. 같은 문서에서 폭·높이를 연속으로 바꾸며 확인했다.
- PVP 안내/Escape, 맵 선택·잠금·검색·빈 결과·필터·지형 미리보기, 협동 방 목록→생성→취소, 비밀방 설정·비밀번호 표시·입력 전달, 대기실 맵 선택·친구 초대, 강화 선택, 일시정지 재개, 비밀방 참가 입력을 확인했다. 브라우저별 8개 조작 검증 묶음이 통과했다.
- 공통 토큰 정리 후 네 브라우저에서 슈팅 팝업/친구 초대의 다크 색상과 테마를 전달하지 않은 공통 모달/검색의 기존 밝은 색상을 추가로 확인했다.
- 실제 Safari, 실제 모바일 기기와 소프트 키보드, 실제 계정·게임 서버에 연결한 협동 전투는 이번 UI 검증에 포함하지 않았다. WebKit 검증을 실제 Safari 검증으로 간주하지 않는다.
- 기존 `auth/server/login-audit.ts`의 동적 파일 경로 추적 경고 6개는 프로덕션 빌드에 남아 있다. 이번 UI 변경과 별개인 기존 경고이며 빌드는 성공했다.
- 검증용 페이지·스크립트·로컬 서버는 검증 후 제거했다. 선택한 시안·화면·결과 JSON은 프로젝트 루트 `artifacts/shooting-dark-ui-2026-11-05/`에 보관한다. 임시 검증 소스를 제거한 뒤 최종 프로덕션 빌드를 다시 생성했다.

프론트엔드 빌드와 실행 환경에 함께 반영한다. 이번 UI 변경에는 백엔드·전투 서버·DB 마이그레이션 변경이 없다.

## 모드 카드 높이 후속 보정

모드 선택 프레임의 남는 높이를 두 카드가 채우도록 세로 Flex 배치를 연결했다. 모험·PVP 카드는 같은 높이로 늘어나고, 이미지가 늘어난 부분을 채워 설명·시작 버튼과 바깥 테두리 하단 사이의 여백을 일정하게 유지한다. 모바일의 단일 열 배치와 필요한 세로 스크롤은 유지한다. 높이 관찰은 다음 렌더링 프레임으로 합치고 실제 값이 바뀔 때만 반영해 WebKit의 ResizeObserver 반복 알림도 방지한다.

Chrome·Edge·Firefox·WebKit에서 각각 10개 뷰포트로 하단 정렬·같은 행 카드 높이·가로 넘침·이미지 크기·PVP 모달을 확인했다(총 40개 크기 검사). 실제 Safari는 미검증이다. 임시 검증 페이지·스크립트는 삭제하고 수정 화면은 `artifacts/shooting-dark-ui-2026-11-05/mode-card-height.png`에 보관했다.
