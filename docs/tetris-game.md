# 테트리스 1인 플레이

## 진입과 화면

- `/games/tetris`는 기존 사이트 헤더·로그인 세션·게임 카탈로그를 재사용한다. `TETRIS / SINGLE`만 등록하며 방·채팅·다인 플레이를 만들지 않는다.
- 기본 게임 외형은 `docs/design/tetris/desktop-lightline-v2.png`, 개인 통계 배치는 `docs/design/tetris/ranking-stats-b.png`를 따른다. 밝은 페이지, 랭킹 카드 안의 개인 통계, 어두운 LIGHTLINE 블록, 좁은 홀드·점수·다음 블록 패널, TOP 100을 구현한다. 최종 판 크기는 시안 이후 요청한 15×25칸을 사용한다.
- 사용자 수정 요청대로 랭킹 아래의 **별도 내 기록 카드**와 **순위 범위/전체 인원 문구**는 제공하지 않는다. 실제 DB의 최고 점수·내 순위·플레이 횟수는 랭킹 제목 아래에 한 번만 표시한다. 카드 내부 폭이 260px 이하일 때에는 세로 행으로 바꿔 라벨과 값을 읽을 수 있게 한다.
- 게임판은 가로 15×세로 25칸이며 숨김 행 2개를 별도로 계산한다. 표시 높이와 사용 가능한 폭을 함께 계산해 셀의 정사각형 비율을 유지한다. 작은 화면은 랭킹을 게임 아래로 배치하고 주요 동작과 터치 조작을 판 아래에 둔다. 540px 이하에서는 NEXT 5개도 판 아래의 한 줄로 옮긴다.
- 낙하 중인 블록과 쌓인 블록은 기존 색상을 불투명하게 채우고 얇은 하이라이트·음영으로 셀을 구분한다. 고스트도 같은 색을 32%로 채우고 밝은 점선을 유지한다. HOLD·NEXT 미리보기도 같은 색을 진하게 채운다.
- Phaser 4.2.1은 인증·게임 이용 확인 뒤 해당 게임에서만 지연 로딩한다. 페이지 이탈·계정 변경 시 엔진, 이벤트, 오디오, 미제출 입력을 정리한다.

## 데스크톱 팝업

- 전체 화면 아이콘 바로 오른쪽의 팝업 아이콘으로 일반 창을 연다. 오목과 같은 기기 정책을 사용하며 모바일·태블릿 UA 및 터치가 주 입력인 기기에서는 표시하지 않는다.
- 공통 창 수명·차단 안내·중앙 배치·원래 창 활성화 기능은 `src/features/games/client/use-game-popup.ts`에서 오목과 공유한다. 테트리스의 최초 크기는 900×1000이며 실제 모니터 작업 영역보다 커지지 않는다.
- 별도의 게임·시작 요청을 만들지 않는다. 고정된 React 포털 컨테이너와 같은 Phaser 캔버스를 옮겨 현재 판·점수·시드·입력 기록·음향 설정을 유지한다. 원본에는 팝업 창 보기와 원래 화면 복귀 안내를 표시한다.
- 팝업에는 게임과 조작을 표시하고 사이트 헤더·푸터·랭킹은 제외한다. 창 크기를 줄여도 15:25 비율을 유지하며 필요한 경우 스크롤한다. 전체 화면은 실제 표시 중인 문서를 기준으로 전환한다.
- 창을 옮길 때에는 일시정지하며 이어서 플레이를 직접 선택한다. 키보드·모달·포커스 상실·숨김 처리는 표시 중인 창에서만 받고, 원본이 숨겨져도 보이는 팝업의 RAF로 고정 tick을 공급한다. 원본과 팝업이 같은 입력을 두 번 처리하지 않는다.
- 팝업 닫기·새로고침·주소 이동은 원래 게임으로 복귀하며 횟수를 집계하지 않는다. 문서 해제 전에 캔버스를 원본으로 되돌려 이벤트와 그래픽 컨텍스트를 유지한다. 원본 화면 이탈·종료·계정 변경은 팝업도 정리한다. 원본 탭은 열어 두어야 한다.
- 원본의 로드된 CSS·CSP nonce·로컬 폰트를 공유한다. CSS 안의 상대 리소스 URL을 원래 스타일시트 기준으로 고정하고 로컬 폰트는 원본에서 읽은 버퍼로 표시한다. 별도 로그인·인증 정보 복제·자식 문서의 opener 권한을 만들지 않는다.

## 규칙 v3

- 60Hz 정수 tick을 사용하는 규칙은 Phaser·React와 분리한다. 서버의 `TetrisReplay`도 같은 시드·명령·tick 순서로 재생한다.
- 7-bag 블록 공급, 다음 블록 5개, 블록당 한 번의 홀드, 고스트, SRS 회전 보정을 지원한다.
- 좌우 이동은 처음 150ms 후 약 33ms마다 반복한다. 소프트드롭도 약 33ms 간격이다. OS 키 반복 속도와 화면 FPS에 의존하지 않는다.
- 착지 후 500ms에 고정하고, 착지 상태에서 이동·회전으로 고정 시간을 최대 15번 갱신한다.
- 줄 제거 점수는 1/2/3/4줄에 100/300/500/800 × 현재 레벨이다. 소프트드롭은 칸당 1점, 하드드롭은 칸당 2점이다. T-spin·콤보·백투백 가산점은 이 버전에 없다.
- 10줄마다 레벨이 오르고 중력 간격은 `max(3, 48 - (레벨 - 1) × 4)` tick이다.
- 방향키: 이동·시계 회전·소프트드롭. Space: 하드드롭. C/Shift: 홀드. P/Escape: 일시정지. X/Z: 시계/반시계 회전.
- 창 포커스 상실·탭 숨김·설정 열기는 자동 일시정지하며 자동 재개하지 않는다. 설정을 열기 직전 플레이 중이었다면 설정을 닫을 때 재개한다.
- 실제 게임 오버가 된 판만 점수와 플레이 횟수를 저장한다. 진행 중 다시 시작·새로고침·페이지 이탈 시 중단한 판의 복원/저장은 제공하지 않는다.

## 저장과 보안

- Flyway V22는 카탈로그의 기존 순서 뒤에 테트리스를 추가하고 `tbl_tetris_run`, `tbl_tetris_player_stats`를 만든다. MVC 서버 재시작 시 적용한다.
- 시작 API는 공통 게임 공개/점검 정책을 다시 확인한다. 계정별로 진행 정보 한 건만 두고 로그인 세션과 플레이 UUID를 결합한다. 다른 탭에서 새 판을 시작하면 이전 판의 제출은 거절된다.
- `POST /api/tetris/overview`, `/start`, `/finish`는 기존 BFF·쿠키·JWT·Origin·브라우저 서명·계정 변경 경계를 공유한다. 신규 인증 쿠키나 공개 기록 변경 경로를 만들지 않는다.
- 시작 UUID 재요청은 같은 시드를 반환한다. 시작만으로 점수·플레이 횟수를 갱신하지 않으며, 서버가 입력을 재생해 게임 오버를 확인한 판만 최고 점수와 플레이 횟수를 한 번 갱신한다. 중도 종료는 클라이언트에서 제출하지 않으며 직접 종료 API를 요청해도 서버가 거절한다. 다시 시작·새로고침·페이지 이탈의 점수와 횟수는 반영하지 않는다.
- Flyway V23은 진행 정보에 규칙 버전을 추가한다. 기존 v1·v2 판은 저장된 버전으로 구분하고 새 판은 v3로 시작한다. 구버전 진행 중인 판은 새 크기로 재생하지 않으며 새 게임을 시작해야 한다. 과거에 집계된 횟수를 소급 추정하거나 초기화하지 않는다. v3 전환을 위한 추가 DB 마이그레이션은 필요하지 않다.
- 종료 요청에는 점수를 받지 않는다. 서버가 시드와 `[tick, actionIndex]` 입력을 재생해 계산한 점수만 최고 기록에 반영한다. 완료 재요청은 중복 집계하지 않는다.
- 한 판은 활성 플레이 최대 216,000 tick(1시간), 입력 24,000개, tick당 명령 4개, 시작 후 경과 2시간까지 제한한다. 실제 경과 시간보다 빠른 tick 제출도 거절한다. 규칙에서 게임 오버로 처리한 1시간 제한은 저장하며, 게임 오버 전 입력 수 한도로 중단한 경우에는 기록을 저장하지 않는다.
- 종료 본문만 300KB까지 허용하고 다른 인증 API의 기존 4KB 제한은 유지한다. Redis에서 계정별 조회·시작·검증 횟수를 제한한다.
- 점수 검증은 임의 점수·잘못된 입력·시간 가속 제출을 막는 범위다. 자동 플레이/봇 탐지는 제공하지 않는다.
- 양수 최고 점수를 가진 활성 회원을 점수 내림차순·회원 ID 오름차순으로 정렬한다. TOP 100은 10개씩 번호 페이지로 조회하며, 개인 통계의 내 순위는 100위 밖도 표시한다. 닉네임은 최신 회원 정보를 사용한다.

## 검증

- 타입 검사, ESLint, Next 배포 빌드, Java 컴파일.
- 15×25 격자·홀드·회전·1~4줄 제거와 512개 클라이언트/서버 재생 경로의 점수·줄 수·보드·게임 오버 일치 확인.
- 독립 MySQL에서 전체 Flyway, 신규 모드, 시작/완료 멱등성, 다른 세션 제출 거절, 100위 제한과 번호 페이지 검증.
- 분리된 브라우저 검증에서 키보드 조작·모달·기록 갱신과 화면 크기별 배치 확인. 임시 테스트 소스는 검증 후 삭제한다.
- v2에서는 시작/재시작 미집계·게임 오버 1회 집계·완료 재요청 멱등성·구버전 거절을 서버 임시 테스트 6개로 확인했다. 임시 MySQL에서 V23과 최초 통계 생성·최고 점수 보존·완료 횟수 증가 SQL을 확인했다.
- v3에서도 서버 임시 테스트 6개로 25행 보드와 실제 게임 오버 집계, 중도 종료 미집계, 완료 재전송, v1·v2 진행 중인 판 거절을 확인했다.
- FHD·QHD·4K·5K·태블릿 2종·휴대폰 2종·가로 휴대폰의 9개 크기에서 가로 넘침, 15:25 비율, 패널 겹침, 랭킹 내부 통계 배치를 검사했다. 실제 Phaser와 화면을 사용한 브라우저 검증은 격리된 테스트 API 응답으로 실행했으며 운영/개발 계정 기록을 변경하지 않았다.
- 팝업은 실제 브라우저에서 동일 캔버스·점수·입력 유지, 키보드·모달·전체 화면, 4개 창 크기, 차단 안내, 닫기·새로고침·재열기·원본 이탈, 게임 오버 1회 집계와 기존 오목 AI 팝업을 포함한 15개 검증을 통과했다. 로컬 폰트 로드를 확인했으며 원본 숨김 처리는 문서 이벤트 시뮬레이션으로 확인했다.
- 점수 저장을 완료 판으로 제한한 뒤 서버 테스트 8개와 브라우저 검증 7개를 통과했다. 미완료 양수/0점 제출 거절, 완료 재시도 멱등성, 일반·팝업의 중도 재시작 미제출, 저장 응답 오류 후 재시도와 통계 갱신을 확인했다. 임시 테스트 소스는 검증 후 삭제했다.
- 블록 색상 채움은 실제 게임의 일반 화면·팝업·390px 모바일 화면에서 블록·고스트·미리보기 표시와 가로 넘침을 확인했다. 게임 규칙·서버 재생은 변경하지 않았다.
