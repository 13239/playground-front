# 유저 관리 · 닉네임 이력 (5단계)

헤더 알림 왼쪽 설정 아이콘 → **유저 관리** 또는 `/admin/users`로 진입한다. 기존 디자인·벡터 아이콘·프로필 캐릭터와 공통 1px 입력 포커스를 재사용한다. 회원 목록은 전체 너비 그리드이며 행을 누르면 중앙 상세 모달이 열린다. 모바일은 표 내부에서만 가로 스크롤하고 상세 내용은 모달 내부에서 세로 스크롤한다.

## 구성

- `users-panel.tsx`: 회원 그리드·검색·상태/동적 역할 필터·10/20/30/50개 선택(기본 10개).
- `user-details-dialog.tsx`: 행 선택으로 여는 상세 모달. Escape·닫기·원래 회원 버튼으로 초점 복귀·배경 스크롤 잠금을 처리한다.
- `user-private-details.tsx`: 허용된 관리자에게 개인정보 원문을 바로 조회·표시한다. 마스킹·열람 사유·별도 열람 버튼·자동 숨김은 없다.
- `user-nickname-history.tsx`: 실제 본인 변경 전/후 이름·시각·변경자와 번호 페이지.
- `numbered-pagination.tsx`: 첫/이전/번호/다음/마지막 이동. 큰 페이지 수에도 최대 5개 번호, 작은 화면은 3개 번호만 표시한다.
- `refresh-button.tsx`: 아이콘 버튼. 클릭하면 시계방향 한 바퀴 회전하며 요청 중 중복 조회를 막는다. 운영체제의 동작 줄이기 설정에서는 회전을 생략한다.
- `user-actions.tsx`: 권한 배정·상태·전체 세션 종료와 확인 대화상자. 권한 배정은 사유를 받지 않고 상태 변경·강제 로그아웃 사유만 필수로 입력한다.
- `user-contracts.ts`: 관리 응답 검증과 안전한 필드 복사.
- 기존 관리자 BFF 허용 목록에 회원별 경로·메서드·조회 조건/본문을 명시적으로 등록한다. 임의 회원 필드·관리자 닉네임 편집 API는 공개하지 않는다.

`USER_READ`가 목록/기본 상세/닉네임 이력에 필요하다. 개인정보는 기존 `USER_SENSITIVE_READ`, 상태는 `USER_STATUS_UPDATE`, 세션 종료는 `USER_SESSION_REVOKE`를 추가로 검사한다. 역할 배정은 현재 ROOT 전용이다. 개인정보 권한이 없으면 해당 영역과 요청을 만들지 않고, 실행 가능한 관리 기능이 없으면 계정 관리 탭을 표시하지 않는다. 최종 권한 판단은 현재 DB를 확인하는 Spring에서 수행한다.

역할 필터와 배정은 이름/코드 전용 `/api/admin/users/role-options`를 검색/커서로 조회한다. 역할 수·고정 4개 컬럼·역할별 회원 수를 넣지 않는다. 라디오 단일 선택은 네이티브 키보드 조작과 공통 포커스를 유지한다.

계정 상태는 ACTIVE(활성)·INACTIVE(비활성)·PENDING(가입대기)·WITHDRAWN(탈퇴)을 공통 계약으로 사용한다. ‘전체 상태’에는 탈퇴 회원도 포함한다. `deleted=true`는 삭제만 뜻하며 삭제된 계정은 서버에서 조회 대상에서 제외한다. 탈퇴 상태 변경은 기존 확인·필수 사유·버전 검증을 사용하고 본인·ROOT는 보호한다. 탈퇴 후 일반 계정 관리와 개인정보 원문 조회를 숨기며 서버도 동일하게 거절한다. 삭제와 탈퇴 복구 기능은 추가하지 않는다.

일반 회원 본인의 탈퇴는 프로필 모달 하단 왼쪽에서 별도로 시작한다. 현재 비밀번호를 확인하고 성공하면 전체 세션 종료·인증 쿠키 정리 후 로그인 화면으로 이동한다. 관리자 본인 상태 변경의 차단 규칙을 우회하는 범용 관리 API는 만들지 않는다. [본인 회원탈퇴 계약과 검증](../../playground-back/docs/account-withdrawal.md)을 따른다.

격리된 응답으로 전체 상태의 탈퇴 행 표시·탈퇴 필터·상태 변경 확인/사유/요청 계약·변경 후 관리 탭과 원문 조회 제한을 검증했다. 상세 재조회 중에는 이전 상태로 관리 폼과 개인정보 조회를 재생성하지 않는다. 브라우저 경고·오류가 없었으며 임시 검증 코드는 삭제했다.

## 회원 목록 재조회

상단 새로고침은 검색어·권한·상태·표시 개수·선택 회원을 초기화하고 10개 표시·1페이지로 다시 조회한다. 개수 콤보박스 오른쪽의 돋보기는 공통 `SearchButton`을 사용하며 확정된 검색어·권한·상태·표시 개수·현재 페이지를 모두 유지한 채 목록만 다시 조회한다. 입력창의 돋보기와 Enter는 입력한 검색어를 적용하고 첫 페이지로 이동하는 기존 동작을 유지한다. 재조회 중에는 새로고침과 조건 유지 돋보기의 중복 클릭을 막는다.

## 계정 관리 화면

승인된 A안의 세로 카드 배치를 사용한다. 권한 배정은 검색 없는 공통 `Select`로 모든 커서 페이지의 권한을 읽으며 ROOT를 선택지에서 제외한다. 한 번에 최대 100개씩 조회하고 필터와 배정이 같은 조회 훅을 재사용한다. 권한 배정의 사유 입력은 제거하고 역할 코드·역할 버전만 전송한다. 권한과 상태 모두 현재 값 → 변경 후 값을 표시하며 선택만으로 저장하지 않는다. 상태는 현재 값을 초기 선택하고 다른 상태를 고르면 변경 버튼을 활성화한다. 활성 계정은 예외적으로 ‘활성 상태 재적용’을 허용해 DB 롤백 후 Redis 차단만 남은 경우를 기존 재활성화 처리로 복구한다. 이 동작에도 사유 입력·확인·버전 검증이 필요하며 이미 종료된 세션은 복원하지 않는다.

상태 변경의 ‘변경 사유’와 세션 종료의 ‘강제 로그아웃 사유’는 필수다. 두 입력은 300자 제한·공백만 입력 금지·인라인 오류·공통 얇은 포커스를 적용한다. BFF도 누락·공백·초과 길이를 거절하며 Spring의 기존 `@NotBlank`·`@Size` 검증을 유지한다. 비활성·탈퇴는 기존 `UserService`를 통해 상태 변경 전에 모든 기기의 세션과 신규 로그인을 차단한다. 명시적 강제 로그아웃은 계정 상태를 바꾸지 않는다. 확인 창·버전 충돌·본인/ROOT 보호·실패 시 초안 유지도 기존 동작을 사용한다.

## 변경 이력과 편집

닉네임은 본인 계정 설정에서만 변경한다. 관리자는 현재/이전 이름·변경 시각·본인 변경 여부를 읽고, 이력을 편집하거나 삭제하지 않는다. 같은 이름 저장은 이력이 생기지 않는다. 저장된 이력을 최신순 타임라인으로 표시하며 실제 첫 페이지의 최신 항목만 강조한다. 좁은 상세창에서는 같은 내용을 레이블이 있는 카드로 표시한다.

회원 상세의 회원 정보·닉네임 변경 이력·계정 관리 탭은 공통 벡터 아이콘을 사용한다. 이력 새로고침은 접근 가능한 이름과 툴팁을 갖춘 공통 아이콘 버튼이다. 하단에는 총 이력 건수·공통 번호 페이지네이션·표시 개수 선택을 배치한다. 이력의 표시 개수는 10/15/20/30개(기본 10개)이며 변경 시 첫 페이지로 이동한다. BFF 요청/응답과 Spring 서비스가 동일한 개수만 허용하고 회원 목록의 기존 개수는 유지한다.

회원 ID·세션 ID·편집 버전이 바뀌면 이전 폼을 재사용하지 않는다. 역할 변경은 `roleVersion`, 나머지 관리 동작은 `managementVersion`을 보내고 충돌 시 입력을 임의로 덮어쓰거나 변경 명령을 재전송하지 않는다. 기존 인증 잠금·갱신·요청 서명과 같은 BFF 쿠키만 사용한다.

개인정보 조회 권한이 있으면 회원 정보 탭에서 GET `/api/admin/users/{id}/sensitive`를 자동 조회한다. 감사 성공 뒤 원문을 표시하며 모달 종료 시 메모리 상태를 해제한다. 브라우저 저장소에 넣지 않는다. 서버/클라이언트 전체 계약과 복구 규칙은 [백엔드 안내](../../../back/playground/docs/user-management-stage5.md)를 따른다.

회원 목록과 닉네임 이력은 `page`(1부터)·`size`를 사용하며 서버의 `page`, `size`, `totalPages`, `totalElements`를 검증한다. 검색·필터·표시 개수가 바뀌면 첫 페이지로 이동한다. 집계는 번호 이동을 위한 응답 정보이며 화면에 회원 수 통계를 추가하지 않는다. 기존 권한·게임·장르·역할 선택기의 커서 탐색은 유지한다. 앞으로 개발하는 화면의 페이징은 페이지 번호를 사용한다.

백엔드 재시작으로 V16을 적용하고 프론트도 재시작/재빌드한다. 이번 그리드 개선에 추가 DB 마이그레이션이나 환경 변수는 없지만 조회 API 계약이 바뀌므로 백엔드와 프론트를 함께 반영한다. [최초 5단계 검증](../../../artifacts/admin-development-stage5/verification.md)과 [그리드 개선 검증·실제 화면](../../../artifacts/admin-user-grid-implementation/verification.md)을 함께 보관한다.
